# 记账小本修复计划

目标：修正手机布局和切换体验，让安卓导入导出、过去日期账单编辑可用，交付可安装 APK 与可复现源码。

架构：保留 React/TypeScript/Vite 前端和原账单结构，增加轻量 Android WebView 容器源码。离线资源固定在 https://app.local/，原生桥仅供本地页面调用。保留旧版 localStorage 键作一次性迁移，以单个快照原子保存新版状态。APK 使用新包名以允许与旧版并存。

## 1. 布局与切换
- 修改 src/App.css、App.tsx、BottomNav.tsx、index.html，移除模板根节点 padding 和手机最大宽度限制。
- 页面状态保持挂载，各页独立滚动；仅激活页做 160ms opacity/transform 动画；遵守减少动态效果设置。
- 原生容器提供沉浸式全屏开关，应用窗口计算刘海、手势和键盘安全区域。
- 验证 320/393/430/768px 宽度无横向溢出，导航不遮住末条流水，切换保留草稿和统计周期。

## 2. 历史流水
- 新增 ExpenseList.tsx、ExpenseEditor.tsx，扩展 useExpenses.tsx 的 updateExpense。
- 首页流水独立日期选择（昨天、今天、全部），统计页显示本期可编辑明细。
- 编辑原 ID/创建时间不变，金额使用正数两位小数，日期有效且不得晚于今天；取消不改变数据。
- 回归测试昨天账单修改金额/日期/备注，刷新后仍保存，统计同步变化。

## 3. 数据与安卓文件交互
- 新增 lib/ledger.ts 数据验证、lib/native.ts 桥接和 DataManager.tsx；兼容旧版 JSON。
- 导入先完整验证、预览数量，再确认替换；覆盖前保存恢复快照；非法文件不改变原数据。
- 主数据持久化先写入成功再更新界面；磁盘写失败显示错误。
- 安卓 ACTION_OPEN_DOCUMENT 读取、ACTION_CREATE_DOCUMENT 写出；取消/失败都返回结果，I/O 在线程中运行。
- 原生接口不允许导航到第三方页面；限制文件大小，避免无限占用内存。
- 验证导出→导入往返，空数据备份、重复 ID、非法日期/金额、旧版缺预算、取消覆盖、恢复备份。

## 4. 构建与交付
- 补齐 android/ 工程、构建脚本、签名材料说明；原签名缺失，不能承诺覆盖升级或读取旧安装私有数据。
- 运行前端构建、核心数据测试和移动浏览器交互测试；构建 APK，检查签名、包名和内置资源。
- 打包 APK、源码 ZIP、修复报告；明确无实机验证的范围。
