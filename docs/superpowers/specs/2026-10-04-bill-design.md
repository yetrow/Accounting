# Bill：本地优先重构设计

目标：保留离线个人记账用途，将账本所有权从 WebView/localStorage 迁移到独立数据库；应用可见名称统一为 Bill。以仓库 main 的 2.0.3 为基线，附件 2.0.0 仅用于旧版兼容验证及用户私有签名材料，不回退仓库已有修复。

## 选择与边界
保留 React + TypeScript 渲染层与离线 Android WebView，使用系统 SQLite，不为改名换包名。与重写 Kotlin UI、整体改为 Capacitor 相比，这条路径能保持升级和原有 WebView origin，降低迁移风险。手写桥拆分为数据库、文件、显示能力与生命周期容器。Android applicationId 仍为 com.jizhang.repaired，显示名 Bill，版本 3.0.0/300。同签名方可覆盖更新。不能绕过 Android 沙箱读取另一个包的数据。

## 数据
实体为账户、分类、交易、月预算。金额用整数分（人民币单币种），账户有期初余额；交易类型为支出、收入和内部转账。转账关联两个不同账户，不计入收支/预算；分类有稳定 ID、类型与归档标记。交易修正/删除更新当前投影，并在同一事务追加包含前后值的审计记录，数据库触发器禁止修改审计记录。不声称完整复式会计系统。

SQLite 的 schema 和顺序迁移文件独立管理；使用外键、金额/类型检查、事务和乐观版本锁。Node 测试运行真实 SQLite，Android 使用系统 SQLite。浏览器开发版使用 IndexedDB 事务，明确与 Android SQLite 实现不同，绝不静默退回 localStorage。localStorage 仅作为旧数据迁移来源。

首次升级读取原 origin 下 Ledger v2 snapshot 或 v1 分散键，完整校验后一次事务迁移，再设置初始化标记。失败不覆盖旧数据、不初始化空账本；保留旧字节以便救援。初始化后的数据库不再读取旧来源。备份导入校验完整后替换投影，同事务保存导入前恢复点，审计不丢弃。支持 Bill v3 JSON、Ledger v1/v2 JSON、CSV 与 Beancount 文本导出；后两者为交换格式，不代替完整备份。

## 核与壳
src/domain：模型、校验、命令、统计、交换格式，无 React、DOM、Storage 依赖。
src/data：Repository、SQLite 投影/事务、IndexedDB 适配；src/platform：类型化原生请求、超时、文件能力；src/ui：异步提交后更新的 React 页面。写入失败保留输入；多窗口版本冲突要求重新加载。原生无网络权限，仅加载原有本地 HTTPS origin；外部导航和子资源拒绝，页面 CSP 禁止外部脚本。

## 体验与工程
主页快捷金额键盘、收支/转账、账户选择、动态预算和流水；统计图包含全部分类名称/占比，窄屏不裁切；设置包含账户/分类管理、备份、恢复和审计历史。系统深色模式、字体缩放、安全区、减弱动效。删除未使用模板组件与依赖。

标准 Gradle Wrapper、固定构建版本、npm lock、CI 测试和 APK 构建。签名从外部环境/CI secrets 注入，绝不入库。可重复构建流程是目标；未独立双构建验证前不宣称 bit 级一致。无真实设备/模拟器时明确区分浏览器、SQLite、编译与实机验证。

本轮不实现云服务、E2EE/CRDT 同步、OCR、通知读取、周期任务；定义同步接口与审计导出基础，UI 明示当前仅本机。启动小于一秒作为后续实机指标，不伪造测量。
