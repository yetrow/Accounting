# 修复与验证报告

日期：2026-09-16。版本：2.0.0 / versionCode 200。

## 原因与对应修改

| 用户反馈 | 原因 | 本次修改 |
| --- | --- | --- |
| 屏幕左右留白，显示不完整 | Vite 模板 #root padding:2rem，手机容器限制 430px，固定导航与页面布局分离 | 移除模板留白；采用全高弹性布局和独立滚动区；导航留在正常布局内；安卓默认沉浸全屏并适配安全区域 |
| 切换不流畅 | 条件挂载切页，每次重建页面、重播饼图动画，多处 transition-all | 保持页面挂载和状态；160ms opacity/transform 动画；禁用重复饼图动画；尊重减少动态效果 |
| 导入/导出无效 | 原 APK 未配置 WebChromeClient 文件选择、下载/原生文件保存，前端只有浏览器 blob 下载 | 原生 ACTION_OPEN_DOCUMENT 读入、ACTION_CREATE_DOCUMENT 写出，后台线程处理 I/O，显式回调取消与错误；浏览器保留标准文件功能 |
| 无法修改昨天流水 | 只有今日列表和新增/删除接口，没有更新接口 | 添加日期/昨天/全部筛选、编辑弹窗，保留 ID 与创建时间，统计同步更新 |

## 已执行的验证

1. 原 APK 内置网页作为基线运行移动布局断言，确实失败：根节点 padding 是 32px，预期为 0px；修复版相同断言通过。
2. `npm run build` 成功：TypeScript 检查与 Vite 生产构建通过。
3. `npm test`：14 项测试全部通过，涵盖旧 JSON 兼容、缺预算、非法金额、非法日期、重复 ID、编辑身份保持、保存失败不丢数据、当前账单与恢复快照原子写入。
4. 移动 Chromium 134 操作测试通过：
   - 320、393、430、768px 无页面横向溢出；
   - 昨天流水编辑金额和备注，刷新后保留；
   - 编辑分类与日期，今日统计同步变化；
   - 切换记账/占比后金额草稿保留；
   - 实际下载 JSON 并验证金额；重新选择 JSON 导入；
   - 取消导入、错误 JSON、有效文件后改选错误文件；
   - 导入空备份后恢复；
   - 本机 JSON 损坏后有效导入解锁，保留原始损坏字符串。
5. Android 源码通过 ECJ 编译、D8 转换、aapt 打包、zipalign 对齐。SDK Platform 35 + Build Tools 35.0.0。
6. `apksigner verify --verbose --print-certs` 成功：v2 / v3 签名均通过。包名 `com.jizhang.repaired`，最低 API 24、目标 API 35。无联网权限，无原生动态库 ABI 限制。
7. 独立代码审查确认恢复快照、损坏数据救援、旧导入预览清除、Android 9–10 刘海区域处理的修正；修正后复查未发现重要遗留问题。
8. 对照 APK 中的 `assets/web` 与 `dist` 检查资源逐字节一致。

## 尚未验证的范围

没有 Android 实机或模拟器连接，因此系统文件选择器实际点击、不同厂商全屏行为、键盘/刘海组合和真实帧率尚未测量。没有宣称达到特定 FPS，也未测试 Play 商店发布（此包用于直接安装）。APK 已构建并签名，不代表已经在用户手机安装验收。

Vite 输出约 636KB JavaScript 的分块体积提示；这是构建提示，不是构建失败。Android 对低版本兼容代码有 deprecated API 提示。未声称全项目 ESLint 通过。

## 原版兼容与数据迁移限制

原上传内容没有安卓源码和原签名私钥。新版补充了完整安卓工程，使用新包名、新签名与旧版并存。无法覆盖升级旧版、无法自动读取旧版私有账单。已有 JSON 备份可导入；旧版导出坏了且没有备份的情况需另行恢复旧数据。**不要卸载旧版。**

## 实机验收步骤

1. 安装修复版，查看两侧背景与底部导航；数据管理中切换全屏开关。
2. 创建昨天的一笔测试账单，在「昨天」列表编辑金额/备注，退出重进确认保留。
3. 导出到 Downloads，再导入该文件并确认数量；取消一次文件选择，确认可以再次打开。
4. 导入前确认已保存真实账单备份；仅用测试数据尝试覆盖与恢复。
